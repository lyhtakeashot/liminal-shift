# 地图视觉口径 —— 《阈限迁移 SHIFT》

> **这份文档是给所有地图相关执行线看的硬约束。2026-11-26 总策划立。**
> 起因：用户 2026-11-26 指出「为什么产出提示词后交给会话构造的地图连游戏地图的核心都丢失了？为什么环岛、公路、树都退化成了几何图形？」
> 根因见 §4。**从现在起，任何只产出几何数据的地图线，都不算交付，只算「几何基线就绪」。**

---

## §0 一句话

**地图不是几何，是贴图。** `data/frames.json` 里的 `rect` / `polygon` / `circle` 只回答一个问题：**「哪里铺什么」**。
它们是**区域声明**，不是画面。画面由引擎按 **32px 一格**把美术素材铺在这些区域里生成。
**一个 shape 只有几何没有贴图 = 一块色块 = 没画。**

## §1 硬约束（不可再讨论）

| # | 约束 | 依据 |
|---|---|---|
| **C1** | **最小单位 = 32×32 px 的一格**。所有地面层素材（草地/土路/柏油/田/河水/山/环岛路缘）都必须是 **32×32 单方格可平铺小件**，或能按 32px 网格切片的图集。 | `docs/待解决事项.md` §1.3 M16（用户 2026-11-25 原话「河流道路环岛都和尺寸无关，我让美术做单方格素材复用就行，美术的重点是复用不是做多设计」）＋ M14（「只需要把区域圈定好（方格），到时候用贴图就行」） |
| **C2** | **地图数据只圈方格区域，不写造型**。新元素（山/丘陵/路标/田地细分/环岛/停车场）一律用 `rect` 或 `polygon` 圈出**方格区域**，造型由贴图决定。**不许**用三角 polygon 假装山、用纯色假装环岛。 | 同上 M14 |
| **C3** | **贴图与地图尺寸解耦**。地图放大 1.5 倍（4800×3600）**不得**导致任何一张地面素材重画。 | M16 |
| **C4** | **美术资产未到位 ≠ 可以用色块顶替交付**。缺图时引擎走色块降级是**容错**，不是**验收通过**。 | 本次事故的直接原因 |
| **C5** | **每一个 shape 都要能说出它铺什么贴图**。写不出 → 这个 shape 不许进 `data/frames.json`。 | C1+C2 的可执行形式 |
| **C6** | **山体与装饰房暂不参与空气墙**（`solid:false` 优先）。「五帧实体空气墙一致」这条**从硬口径降级为待办**：不再为了对齐而往帧里补山 / 补实体房，**等后续几张地图全部定稿后，再统一一次性补**。 | 用户 2026-11-26 原话：「现在先不要加装饰房和山作为空气墙，加上去对后续几张地图来说是多余的束缚，等后续几张做完后再加」 |

## §2 数据长什么样（形状 → 贴图 的对应表）

| shape | 含义 | 贴图来源 | 平铺？ |
|---|---|---|---|
| `rect` + `label:""` | 地面铺装区（草地/土黄地） | `ground_<帧>_tiles.png`（32×32） | **是**，逐格铺满 rect |
| `rect` + `road:true` | 路面区 | `road_<帧>_tiles.png`（32×32，土黄 #8a7a5a / 柏油 #56564f） | **是** |
| `rect` + `label:""`（田块） | 田地区 | `field_<帧>_tiles.png`（32×32） | **是** |
| `polygon` + `label:"河"` | 河水区 | `river_<帧>_tiles.png`（32×32） | **是**，按 polygon 内格铺 |
| `polygon` + `label:"路"`（环道） | 环岛车道 | `roundabout_curb.png` + `road_<帧>_tiles.png` | **是**，路缘另铺一圈弧段 |
| `polygon` + `label:"岛"` | 环岛内岛 | `roundabout_island_soil.png`（2001 工地态）/ `roundabout_island_green.png`（2026） | **是** |
| `polygon` + `label:"山"` | 山体 | 山地表贴图 + 轮廓（32×32 网格切片） | **是** |
| `circle` + `label` 含「槐」 | 老槐树 | `tree_<帧>.png`（独立贴图，按半径居中、底边对齐） | 否，整张贴 |
| `circle` + `label` 含「井」 | 老井 | `well_<帧>.png`（整张贴） | 否 |
| `house` | 房屋 | `assets/village/houses/<族>/<帧>_{base,roof}.png`（有则整张贴，无则色块降级＋登记缺口） | 否 |

> 环岛零件清单已在 `docs/ART-GAP-A4A5.md` §5 C 组给出（3 张 32×32：`roundabout_curb` / `roundabout_island_soil` / `roundabout_island_green`）。

## §3 引擎必须提供的能力（当前缺什么）

| 能力 | 现状 | 归属 |
|---|---|---|
| 32px 贴图**平铺**填满 rect | ❌ `world_view.gd:219-229`（路）、`:242-252`（田）都是「整帧 bbox 贴一次整张大图」 | **L8** |
| 地面铺装（草地） | ❌ `world_view.gd:165` 只 `draw_rect(全屏, ground 颜色)`，磁盘上的 `ground_a1..a3_tiles.png`（32×32）**零消费点** | **L8** |
| polygon 按区域平铺 | ❌ `world_view.gd:260-271` polygon 分支**只认河**，且河贴图画布写死 `Vector2(3200,416)` | **L8** |
| 山/环岛/内岛按 label 分派贴图 | ❌ 同上，山 polygon 现在只会被 `draw_colored_polygon` 画成纯色三角 | **L8** |
| 河覆盖全宽 4800 | ❌ 河贴图 3200 宽，A1–A3 的河在 x=3200 处**视觉断掉**，A4/A5 却是 152 点铺到 4800 ⇒ **跨帧河宽不一致（现存视觉缺陷）** | **L8** |
| A4/A5 的 6 栋房屋底图/屋顶图 | ❌ `world_view.gd:666-673` `FAMILY` 只登记 A1–A3 的 12 个 id ⇒ A4/A5 走色块墙+色块屋顶 | **L8 + 美术** |
| A4/A5 的树/井/路/田场景图 | ❌ `asset_draw.gd:18-40` `SCENE_FILES` 只有 a1/a2/a3 | **L8 + 美术** |

**Godot 已有能力，不用新造**：`CanvasItem.draw_texture_rect(texture, rect, tile, modulate, transpose)` 的**第三个参数就是 `tile`**。
现有代码 `world_view.gd:225/236/248/264` 全都传 `false` —— 改成 `true` 就能平铺，但**前提是贴图本身就是 32×32 的单方格**（现在贴的是 3200×416 的大图，平铺无意义）。
所以 L8 的真正工作量是：**把「整帧大图」这套管线换成「32px 单方格逐格铺」**，再把美术同学交付的 autotile 图集切进 `assets/village/scene/`。

## §4 这次事故的根因（四层，都要堵）

1. **任务书层**：A5 v5 / A4 重排两份地图任务书里「贴图」「平铺」「32×32」「美术」**零命中**，验收项只有「几何自检 errors=0」「回归全绿」「空气墙 IoU 100%」——**全部在验几何，没有一条验贴图**。执行线照做，几何满分，画面是色块。
2. **引擎层**：`world_view.gd` 只会贴整帧大图，polygon 分支只认河 ⇒ **环岛、山、竖路、地面在引擎层面根本没有贴图通路**。这不是执行线的错，是没有这条线。
3. **资产层**：美术同学的 **32px autotile 图集已交付**（`美术资产/地皮/`、`美术资产/树/`、`美术资产/房屋/`，如 `GK_A2_CCautotile_1.png` 768×576＝24×18 格、`GK_B_CC_1.png` 768×768＝24×24 格，全部 32px 对齐），但**未入库、未接线**；`assets/village/scene/` 里仍是 A1–A3 的旧整帧大图。
4. **纪律层**：M16/M14 早在 2026-11-25 就写进 `docs/待解决事项.md`，但**一直没被转成任何一份可执行的任务书**；L8「资产接线」任务书长期缺位（我自己也多次记「L8 任务书未写」）。**规则不落到任务书里，就等于不存在。**

## §5 地图线交付前的必查清单

任何交付了 `data/frames.json` 的线，交卷前必须逐条回答：

- [ ] 每个新 shape 的**贴图来源**是哪张图？（写不出来 → 不许进数据）
- [ ] 缺图的地方，是否已在反馈文档里**登记为美术缺口**并列出文件名与尺寸？（不许静默留色块）
- [ ] 32px 单方格素材是否已入库到 `assets/village/scene/`？引擎是否已有平铺通路？
- [ ] 五帧之间的**地面材质**是否一致对应（A1 土黄路 / A3+ 直路 / A5 柏油）？
- [ ] 五帧的**河**是否覆盖同一宽度区间？
- [ ] 几何自检之外，是否有一张**实机截图**证明「这不是色块」？

**只要第 1 条或第 6 条不过，验收结论就是「几何就绪，视觉未交付」。**

## §6 实测附录 · L8 资产接线执行后（2026-11-26）

> 只记实测，不改上文规则与结论。完整证据见 `docs/FEEDBACK-asset-tile-wire-exec.md`。

**能力面（§3 表的状态已变）**
- 平铺通路已启用：`world_view.gd` 里地面 / rect `road:true` / rect `label==""`（田）/ polygon `河` / polygon `路` 五处改走 `draw_texture_rect(tex, rect, ***true***, sc)`。上文 §2 提到的 `draw_texture_rect` 第 3 参（tile）现在**确实传 true**，且经窗口渲染回读证明生效。
- 旧的「整帧 bbox merge 成一个大矩形贴一张大图」逻辑（`_scene_bboxes()`）**已删除**；`world_view.gd` 的对应行号也整体位移，上文 §2 引用的 `:225/236/248/264` 已过期。

**像素实测（1280×720 根窗口 / OpenGL Compatibility / RTX 5060）**
`TILE_WIRE_CHECK_DONE fails=0 gaps=4 checks=39`：地面五帧每 32×32 格内 **3** 色；`rect[田块]` 五帧 **5** 色；`rect[公路]` 与 `polygon[路]` **3** 色（A1–A4 #8e7148 土黄 / A5 #57564f 柏油）；`polygon[河]` 五帧 **3** 色 #3f5f6e；`polygon[岛]` / `polygon[山]` **1** 色（缺口，已登记）。A4 河 `x=4700` 仍是水 ⇒ 引擎已铺到 4800。

**两处与上文说法不符的实测**
1. §4 第 3 条称 `美术资产/` 的 autotile 图集「全部 32px 对齐」。实测（`lab/_l8_grid.py` 重复块检测）32px 对齐率只有 **38%**（`GK_A2_CCautotile_1.png`）/ **9%**（`GK_A5_CCfloors_1.png`），16px 重复率 81% / 52%；且主色是蓝绿（#6dac65 / #dada76 / #355671），与 A4 土黄 #8a7a5a、A5 柏油 #56564f 不匹配。**结论：这两张图集不适合直接切 A4/A5 的地面/路面瓦**，本线改用「既有纹样 + 按帧色重新调色」的临时瓦（用户 2026-11-26 批准）。
2. §4 第 3 条说 autotile 图集「未入库」，这条现在仍然成立 —— 本线只入库了 6 张切好的临时瓦（`*_l8.png`），原图集仍留在 `美术资产/`（未跟踪、未入库）。

**还没堵的洞**
- 环道路缘 `roundabout_curb.png` 需要「按角度旋转瓦片」的能力，引擎目前没有 ⇒ 环道现在是一整片路面瓦（无路缘、无白导流线）。
- 山地表瓦片 B/C 组都没定名。
- A1–A3 的河数据只画到 `x=3200`（A4/A5 是 4800），引擎侧已能铺，剩数据侧。
