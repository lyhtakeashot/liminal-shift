## §1. 一句话

一个被世界遗忘的侦探，在同一个村庄里走了五次，
把一件被四代人层层埋掉的案子，归档。

**玩法**：固定一屏，只能沿时间或空间其中一个轴移动，按 Shift 切换。

## §2. 操作规范（核心）

### 2.1 三个键位

| 键 | 空间轴 | 时间轴 |
|---|---|---|
| **W** | 向上走 | **向未来**（下一帧） |
| **S** | 向下走 | **向过去**（上一帧） |
| **A / D** | 向左 / 右走 | **无作用** |
| **Shift** | 切到时间轴 | 切到空间轴 |

### 2.2 一句话概括

> **Shift 只做一件事：切换轴。**
> **切换之后，同一组方向键含义变了。**

**这是整个游戏唯一的机制。** 不要加跳跃，不要加攻击，不要加交互键以外的任何东西。

### 2.3 两种模式的区别

| | 空间轴（Space） | 时间轴（Time） |
|---|---|---|
| 角色 | **真的在走**，位置变化 | **原地走**，位置不变 |
| 世界 | 静止（当前帧冻结） | **流动**（帧在前进/后退） |
| 按键效果 | 移动 | 推进/回退时间 |
| 碰撞 | 当前帧的碰撞体 | **目标帧的碰撞体**（见 §3.3） |
| 画面 | 彩色、清晰、稳定 | 去饱和、角色是唯一有颜色的、轻微色差 |
| 边缘 | 无 | 暗角收紧 |
| 声音 | 正常干声 | 低频衰减、脚步声音高随速度变 |
| 时间轴 UI | 收起 | 展开，显示刻度 |

### 2.4 「角色走动但位置不变」

时间轴模式下，角色播放走路动画，**但坐标不动**，世界在他周围溶解。

**必须满足三个条件才成立**：
1. 镜头**完全不动**
2. 世界在动（帧在推进）
3. 角色身后**有残影拖尾**

否则玩家会以为操作失灵。

### 2.5 输入处理骨架

```gdscript
enum Axis { SPACE, TIME }

var axis: Axis = Axis.SPACE
var frame: int = 0          # 当前帧索引
var frame_max: int = N - 1
var character_pos: Vector2  # 空间轴的位置，切到时间轴时冻结

func _unhandled_input(e: InputEvent) -> void:
	if e.is_action_pressed("shift_axis"):
		axis = Axis.TIME if axis == Axis.SPACE else Axis.SPACE
		_on_axis_changed()
		return

	if axis == Axis.SPACE:
		# 正常的 8 向 / 4 向移动
		pass
	else:
		# W/S 推时间，A/D 无作用
		if e.is_action_pressed("move_up"):
			_try_step_time(+1)
		elif e.is_action_pressed("move_down"):
			_try_step_time(-1)
```

**关键**：`W/S` 在两个轴里复用同一个 action。不要另建 `time_forward` / `time_back` action，
**复用 `move_up` / `move_down`**，语义靠 `axis` 状态分派。

### 2.6 需要在 Project Settings 里建的 action

| Action | 键 |
|---|---|
| `move_up` | W，↑ |
| `move_down` | S，↓ |
| `move_left` | A，← |
| `move_right` | D，→ |
| `shift_axis` | Shift |

**注意**：`shift_axis` 用 `is_action_pressed`，**不要用长按**。
早期讨论过「轻按跳 / 长按擦」，**已废弃**——现在 Shift 是纯粹的模式开关。

## §3. 时间系统

### 3.1 五帧

| 帧 | 年份 | 村子 | 案件 |
|---|---|---|---|
| **A1** | 1926 | 三房、弯路、两田、磨坊、井 | 陆文溺亡 |
| **A2** | 1951 | 陆家房空、老井封、新井在路另一头 | 陆敬之被推进井 |
| **A3** | 1976 | 路还弯、草长、农田半荒、磨坊改粮站 | 方师傅被封进地基 |
| **A4** | 2001 | 路开始取直、粮站拆、超市在建、农田全荒 | 改地质报告 |
| **A5** | 2026 | 笔直十字路口、超市、玩具店、小学 | 沈明远什么都不知道 |

**每代都是 36 岁**（隐线，归档表上五行连续 36 时会让人发毛）。

### 3.2 帧有两类

| 类型 | 数量 | 作用 | 成本 |
|---|---|---|---|
| **锚点帧** | 5（A1–A5） | 可探索的时间节点 | 高 |
| **过渡帧** | 每个间隔 4–5 张，共 ~20 | 让时间变化看起来自然 | 低（大量复用） |

**总计约 25 帧**，对上你说的 25~30。

**过渡帧本身就是内容**：有些线索只在过渡帧可见（比如 A3→A4 之间「地基挖开还没回填」的窗口）。
**否则玩家只会按一下 Shift 直接跳到目标年代，中间 20 张白做。**

### 3.3 碰撞：这是最大的坑

**`visible = false` 不会关闭碰撞。** 这是 Godot 的既定行为。

意味着：如果你靠切可见性来刷时间，**25 个帧的墙会同时生效**，
玩家会被 1926 年那堵早就拆掉的墙挡住。

**正确做法：在 base 场景的根节点挂一个脚本，统一管。**

```gdscript
extends Node2D

func set_active(on: bool) -> void:
	visible = on
	for s in find_children("*", "CollisionShape2D", true, false):
		s.set_deferred("disabled", not on)
	# 顺带：隐藏的帧不该跑动画/逻辑
	process_mode = Node.PROCESS_MODE_INHERIT if on else Node.PROCESS_MODE_DISABLED
```

时间轴管理器只调 `set_active(false)` / `set_active(true)`，不碰内部。

### 3.4 时间轴移动的碰撞判定

时间模式下角色位置不变，但每推进一步都要检查：

> **如果目标帧里，角色的碰撞盒和固体重叠 → 卡住，推不过去。**

**反馈不要「弹回去」**（那是惩罚），要「顶住了」：
- 轻微顿帧
- 屏幕轻微震动
- 低频闷响

### 3.5 场景继承链（实测过）

用 Godot 的**继承场景**做帧，每帧只存相对上一帧的改动。

**30 层实测数据**（真的测了 30 层，不是估的）：

| 项 | 数据 |
|---|---|
| base 场景 | 2800 B |
| 每帧增量 | **约 225 B** |
| 30 帧总计 | 9563 B |
| 若全量复制 | 84000 B |
| **加载 30 帧** | **34.4 ms** |
| **实例化 30 帧** | **3.9 ms** |
| **刷完 30 帧 ×60 遍** | **2.66 ms**（1800 次切换） |

**性能完全不是问题。**

**但继承是纯累积的**：第 29 帧 = 前 29 帧所有差分的和。忘了恢复的永远回不来。
好消息是**可以覆盖**（实测 `visible` 能改回 true），但必须**显式写出来**。

### 3.6 继承结构建议：分叉，不要长链

```
				base.tscn（所有元素、原始位置、默认状态）
			   ╱     │      │      │      ╲
			A1     A2     A3     A4     A5        ← 5 个锚点帧，各自继承 base
			│      │      │      │      │
		 t1_1   t2_1   t3_1   t4_1   (终点)
		 t1_2   t2_2   t2_2   ...
```

| | 长链 | 分叉（推荐） |
|---|---|---|
| 看某帧全貌 | 得加 20 个文件 | **一个文件，几行** |
| 某段出错 | 污染后面所有 | **只影响本段** |
| 过渡链长度 | 24 | **4~5** |

**过渡链超过 5 张玩家分辨不出来。**

## §4. 故事怎么放进玩法（给关卡设计）

完整故事在 `docs/story.md`。这里只给**映射**。

### 4.1 三段式揭晓

**每一段必须落在不同帧，逼玩家来回刷。**

| 阶段 | 帧 | 拿到 | 卡在哪 |
|---|---|---|---|
| **证词** | A3 | 真本《水簿》 | 只有自述，没有旁证 |
| **模式** | A4 | 土地登记表第二联 | 只有钱的痕迹，没有性质 |
| **铁证** | A5 | 周有田往来账 | 完成反转 |

**这就是为什么玩家必须来回走，而不是一路向前。**

### 4.2 归档表

玩家最后填三个空，判定坐标：

```
埋尸位置：＿＿＿＿
埋葬人数：＿＿＿＿
最早一具：＿＿＿＿
```

**正确答案**：十字路口那块圆形补丁下面 / 三 / 1951。

**「未确认」这三个字本身就是玩法**：查到 A3 时表格显示"1951 事件性质：未确认"。
它指方向，不给答案。

### 4.3 三条写作纪律（违反就破坏设计）

1. **只写看到什么，不写意味着什么**
   - ✅「地上有一圈比周围颜色深的方形痕迹」
   - ❌「这里曾经有一座建筑」
2. **日记只记行为和数字，不记判断和动机**
   - ✅「放水三刻。未告陆家。」
   - ❌「我很内疚，但我不敢说」
3. **真相不能靠「又发现一份文件」**
   - 双日记全片只用一次，其余必须是物理证据（补丁、排水管、树倾斜、界碑）

## §5. 美术规范（给搭档）

### 5.1 分辨率

| 项 | 值 |
|---|---|
| 内部分辨率 | **640 × 360** |
| 缩放 | 整数倍（3x → 1920×1080） |
| 风格 | 像素风，俯视 3/4（星露谷式） |
| 光线方向 | **统一从左上来** |

**这个数一旦定了就不能改**，改了所有素材重画。

### 5.2 图层拆法：省六倍工作量

**不要每帧都画完整画面。** 你的 25 帧 × 10 个元素 = 300 张图，画不完。

拆成三层：

| 层 | 是什么 | 数量 | 谁做 |
|---|---|---|---|
| **base** | 轮廓/结构（房子→废墟→空地） | ~30 | 美术 |
| **overlay** | 裂缝、杂草、焦痕、木板、碎石、脚手架 | ~14 | 美术 |
| **tint** | 年代调色板 | 0 张 | 程序 |

```
30 + 14 = 44 张图  →  撑起 25 帧
```

**从 300 降到 44，六倍。**

**overlay 是跨元素复用的**：一片杂草能盖在小路、农田、房子墙根上。
**base 是仓库，overlay 是 diff，tint 是分支颜色。**

### 5.3 过渡帧不用画

如果状态是**数据**（不是 25 个手摆的场景），两个状态之间插值就得到过渡帧：

- overlay 透明度 lerp（杂草慢慢长出来）
- tint lerp（暖黄 → 病绿 → 灰褐）
- **只有结构性变化需要手画关键帧**（房子塌了、路铺柏油）

**25~30 帧在这个架构下不是 30 张图，是 30 个数据点。**

### 5.4 元素清单

| 元素 | 是什么 | 状态数 |
|---|---|---|
| `house_a` `house_b` `house_c` | 三栋农舍 | 各 3–4（完整/破损/坍塌/拆平） |
| `road` | 弯曲小路 → 柏油直路 | 3–4 |
| `farm_1` `farm_2` | 两片农田 | 各 3（作物/荒草/停车场） |
| `well_old` | 老井（核心物证） | 4（开挖/封盖/锁死/水泥封） |
| `well_new` | 新井（A2 起出现） | 2 |
| `mill` | 磨坊 → 粮站 → 拆平 | 3 |
| `tree` | 老槐树（贯穿全片的唯一生命） | 4（树苗/中/大/树桩） |
| `fence` | 围栏（缺口位置始终不变） | 2 |
| `market` | 超市（A4 起） | 2（在建/建成） |
| `toyshop` | 玩具店（A5） | 1 |
| `crossroad` | 十字路口 + 圆形补丁（A5 核心物证） | 2 |
| `signpost` | 界碑（字磨掉一半） | 1 |

### 5.5 文件名约定（掉落即用）

```
assets/village/
├── elem/
│   ├── house_a/  intact.png  damaged.png  rubble.png  flat.png
│   ├── road/     dirt.png    overgrown.png  asphalt.png
│   ├── tree/     small.png   mid.png  large.png  stump.png
│   ├── well_old/ open.png    covered.png  sealed.png  concreted.png
│   └── ...
└── overlay/
	├── weeds_a.png  weeds_b.png  weeds_c.png
	├── crack_a.png  crack_b.png
	├── soot_a.png   soot_b.png
	├── boards_a.png boards_b.png
	├── rubble_a.png rubble_b.png
	└── scaffold.png
```

**代码按 `"house_a/intact"` 这种字符串去 `load()`。**

**缺文件时自动退回纯色占位块**（尺寸和锚点正确）。
**美术丢进对应文件夹、起对名字，游戏里立刻就是正确的东西——不需要等。**

### 5.6 锚点规范

每个元素的画布要告诉美术三件事：

| | |
|---|---|
| 画布尺寸 | 比如房子 96×112 |
| **锚点** | 底部中心 = 贴地那一点（像素坐标 48, 112） |
| 朝向 | 俯视 3/4，光从左上 |

**给美术一张带网格的模板图，比写一百句描述有用。**

### 5.7 AI 辅助美术的前提

搭档用 AI 生成素材时：

- **所有素材必须统一调色板和光照方向**，否则拼在一起会散
- AI 出的图**要人工修一遍边缘和锚点**，直接塞进去会错位
- **overlay 必须透明底**，AI 容易出白底
- 比赛规则：**AI 允许，但提交时要申报**（`docs/story.md` 里有对应记录）

### 6.1 `project.godot` 要改的五处

**当前是引擎默认模板，全部要改：**

```ini
[application]
config/features=PackedStringArray("4.7", "GL Compatibility")   ; ← Forward Plus 改掉

[display]
window/size/viewport_width=640                                  ; ← 新增
window/size/viewport_height=360                                 ; ← 新增
window/stretch/mode="canvas_items"                              ; 已对
window/stretch/aspect="keep"                                    ; ← expand 改 keep

[physics]
; 3d/physics_engine="Jolt Physics"                              ; ← 整行删掉（纯 2D）

[rendering]
renderer/rendering_method="gl_compatibility"                    ; ← 新增
renderer/rendering_method.mobile="gl_compatibility"             ; ← 新增
; rendering_device/driver.windows="d3d12"                       ; ← 删掉
textures/canvas_textures/default_texture_filter=0               ; ← 新增（Nearest，像素画必须）
```

**为什么必须改 Compatibility**：
Forward+ 的 Web 导出在某些集显机器上**直接白屏**，
而互评的人大多数用集显笔记本浏览器打开。
**比赛要求浏览器能玩，这是硬性技术前提。**

**为什么必须 Nearest**：像素画用线性过滤会糊成一团。

### 6.4 已知的技术陷阱

| 陷阱 | 后果 | 解法 |
|---|---|---|
| **`visible=false` 不关碰撞** | 25 帧的墙同时生效 | §3.3 的 `set_active()` |
| `[s]` 删除线太细 | 看不清，白做 | 自绘（§6.3） |

| 假本漏处理 `---` | 页面上露出裸的 `---` | 两套渲染都要处理所有标记 |

| **MCP 的 `add_node` 写不了 Vector2** | 位置/缩放静默丢弃 | **场景属性直接改 `.tscn` 文本** |

## §6.5 Git：本地 init 与远程推送是两回事

**是的，`git init` 只是在本地建仓库。** 它不联网、不需要账号、不碰 GitHub。

```
git init      → 在本机创建一个 .git 文件夹（本地版本库，仅此而已）
git remote add → 告诉本地仓库"远程在哪"（仍然不联网）
git push      → 这才真正联网上传到 GitHub
```

**三步是分开的，顺序不能乱，也不需要一次做完。**

### 6.5.1 现在这一步：本地 init + 首次提交

**在项目根目录 `shift/` 执行**（PowerShell）：

```powershell
cd "D:\Desktop\VibeCoding\godot_project\github_game_off_shift\shift"

git init
git add -A
git commit -m "chore: 初始化项目，故事文档与转接文档"
```

**此时已经可以开始正常开发了。** 之后的提交：

```powershell
git add -A

```

### 6.5.2 明天做完草稿后：推到 GitHub

1. 在 GitHub 网页上 **New repository**，名字随意（比如 `shift`），
   **选 Public**（比赛硬性要求公开），**不要勾选** "Add a README" / ".gitignore"
   —— 因为本地已经有这些文件了，勾了会产生冲突。
2. 复制页面给的仓库地址，然后：

```powershell
git branch -M main                                  # 分支名统一成 main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

**`git remote` 和 `git push` 需要 GitHub 账号认证**（首次会弹浏览器登录，或要填 PAT）。

### 6.5.3 现有配置文件可直接用

项目里已经有两份**引擎自带的、正确的**配置，不用重写：

| 文件 | 内容 | 状态 |
|---|---|---|
| `.gitignore` | `.godot/`、`/android/` | ✅ 正确，`.godot/` 是导入缓存，不该进仓库 |
| `.gitattributes` | `* text=auto eol=lf` | ✅ 正确，统一换行符，跨平台协作必须 |

**注意**：`.godot/` 被忽略是对的。但如果美术和程序员用不同机器，
`assets/` 下的 `.import` 文件**应该提交**（不要加进 `.gitignore`），
否则别人的机器上资源路径会重建出错。

## §9. 和 SHIFT 主题的关系

**写进 itch 页面的介绍里，这是评委第一个看的：**

> **主角唯一能移动的维度是时间，而一百年里唯一没有移动过的东西，是那块地砖。**

空间冻结、时间可动、位置不变——**这既是玩法，也是这个故事的主题。**

**另外一句**（用来解释为什么没有 NPC）：

> **1953 年知情的人死了。1978 年知情的人死了。2003 年知情的人搬走了。2026 年村里没人了。**
> **所以玩家只有物件——这是剧情的必然，不是风格的选择。**
