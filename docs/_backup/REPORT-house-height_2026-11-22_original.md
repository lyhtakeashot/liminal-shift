## 一、起因与结论

**起因**：美术看截图反馈「现在的房子都太小了，主角都有 1×2」。

**结论：房子的绝对尺寸不小，是三个因素叠加出了「小」的观感。**

1. **视口** — 内部 640×360，在本机（1707×1067）只能整数 2 倍 → 每格 32 屏幕像素。星露谷是 16×4 = 64 屏幕像素/格，**我们每格只有它一半**。
2. **屋顶不做遮挡处理** — 伪 3D 屋顶「无论如何都画」，玩家一进屋整栋被盖住，看不见房间。
3. **房间高度** — 改前 85 间房的高度中位数正好 = 2 个主角高，其中 16 间（19%）≤2 格，主角顶天立地。

**量级对照（说明「不小」）**：陆家 20×10 = 320×160px，星露谷农舍 9×5 = 144×80px，**面积是 4.4 倍**；沈家 A3 是农舍 7 倍多。

**用户已拍的方向**（原话）：「文字标签只是暂时用来区分地块的，等美术资产上线后，就会全部撤掉。我在比较的是场地大小（房间）和人做对比」——**否决标签类方案，只做房间加高**。随后拍板执行：「帮我写一下吧，确实需要加高，不然太拥挤了」。

## 六、接手者的注意事项（踩过的坑）

- **`greybox_check.gd` 的 exit code=1 是正常的**（脚本自身 quit 方式），判定看布尔行。重定向到文件偶发 0 字节，直接管道抓 stdout 才可靠。
- **GDScript 类型坑**：`Dictionary.get("pos")` 返回 Variant，赋给 `Array` 型变量会报 `Trying to assign value of type 'Vector2' to a variable of type 'Array'`。要么 `var p: Array = d.get("pos",[0,0])`，要么直接 `Vector2(d["pos"][0], d["pos"][1])`。
- **数据结构语义**（本会话踩过两次）：`lot` 是**闭区间** `[x0,y0,x1,y1]`；`wings` 是 `[x,y,w,h]`；家具 `rect` 是 `[x,y,w,h]`（宽高，不是角点）。
- **`_shot_p3d.gd` 必须带窗口跑**，不能 `--headless`（要取 viewport texture）。
