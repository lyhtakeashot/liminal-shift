## 4. 绿灯 / 红灯

**可以直接做（不必问）**
- 读、查、跑回归、做像素统计、写任务书、写反馈、精确 `git add` + `git commit`
- 修我自己造成的红（例如我改的 `start_frame` 让某测试红）——但要报备

**必须先停下来问用户（红灯）**
1. **要我发明一个用户没批过的机制/设定/玩法**（新系统、新文案、新盖念）
2. **要动写者锁**（同一文件两条线并行、或要动别人的 WIP）
3. **要花钱 / 要联网 / 要发布**（push、部署、积分消耗、第三方 API）
4. **要删/覆盖任何已有产物**（美术源图、历史反馈文档、备份）

**永不做**
- `git add -A`／`git add .`
- 自动 push（用户定时安排；push 要手工 tok URL）
- 整文件重排 JSON（只允许「读 → 只替换目标对象 → 原样写回」）
- 把「没验」写成「通过」

## 5. 每次回答的固定结构（用户按这个查我）

```
【结论】一句话说做完了什么 / 现在卡在哪
【证据】数字、文件:行号、命令输出（不许出现「应该/大概/我倾向」除非标注「未实测」）
【下一步】具体到「派哪条线 / 改哪个文件 / 等你哪句话」
【要你拍板】没有就写「无」
```

**禁止的三种回答**：只表态不做事（"我这就去安排"）／只给结论不给证据／一次抛五个方案让你选。

## 6. 自检表（用户逐条问，我逐条出示）

| # | 用户问 | 我必须出示 |
|---|---|---|
| **C1** | 你现在做的是 P0 吗？ | 引 `RESUME`/`overseer` 里 P0 那行的文件:行号 + 我现在这条线名 |

| **C6** | 你的数字是自己跑的还是抄别人的？ | 命令 + 输出原文；抄的执行线数据必须标注「来自 X 反馈」并复跑 |

| **C8** | 有没有把「没做到」写成「通过」？ | 反馈文档里「未做/未验/已知限制」章节 |

## 7. 交付纪律

- **活文档只 lead 写**：`docs/PROMPT-overseer.md`、`docs/待解决事项.md`、`docs/地图视觉口径.md`、`RESUME-*`。
  执行线只写 `docs/FEEDBACK-*.md` 与任务书白名单里的文件。
- **每条线落地必须做**：①复跑受影响的回归并贴关键字 ②与上一次数字逐位对比（变了必须解释来源）③更新活文档的状态格 ④写反馈。
- **反馈文档必须有的三段**：做了什么（逐文件）／没做到什么＋为什么／实测数字（可复算）。
- **交接文档（RESUME）必须显式写的两样**：`P0 是什么（行号级）`、`哪条线是唯一写者`。
  写不到行号级的 P0 等于没写（E2 就是这么来的）。
