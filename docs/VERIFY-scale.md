# 真机验收清单：TILE32 fractional 缩放（1080p 1.5× 脉动）

> 状态：2026-11-21 用户已拍板**接受 fractional 缩放**，本清单是开美术线前的最后一道 gate。
> 验收人：用户本人（观感必须人眼判断，Agent 无法代劳）。
> 数学证据：`lab/verify_scale.py`（可直接跑，纯标准库）。

---

## 0. 为什么要验

视口 1280×720 + `scale_mode=0`（fractional）+ Nearest 过滤 + aspect=keep。

| 屏幕 | 缩放比 | 一格物理尺寸 | 格线脉动 | 结论 |
|---|---|---|---|---|
| 窗口 1280×720 | 1× | 32 px | 0 px | 整数倍，无脉动 |
| **1080p 1920×1080** | **1.5×** | **48 px** | **1 px（周期 2）** | ⚠️ 唯一需要真机看的档 |
| 1440p 2560×1440 | 2× | 64 px | 0 px | 整数倍，无脉动 |
| 4K 3840×2160 | 3× | 96 px | 0 px | 整数倍，无脉动 |

`lab/verify_scale.py` 实测输出（1080p）：

```
scale          = 1.5000 (非整数 ⚠ 有脉动)
内容区         = 1920x1080 物理像素
横向逻辑列宽   = 周期 2: [1, 2]
脉动幅度       = 横 1 px / 纵 1 px
一格=32逻辑像素 = 16 个宽度周期
```

数学结论：**1px 的粗细交替是 Nearest 采样的必然结果**，周期 2（一条逻辑像素 1px、下一条 2px）。
换线性过滤能消除但像素画会糊——所以保持现状，只验观感能否接受。

一格 48 物理像素里 1px 的差 ≈ 2%，静止时基本不可见，**滚动时可能表现为格线轻微"呼吸/毛刺"**。

## 1. 🔴 最重要：截图方式

**不要用 Godot 的截图脚本**（`_mdtest/_shot_*.gd` 里的 `get_viewport().get_image()`）。
它截的是 1280×720 逻辑图，脉动发生在 OS 合成/缩放阶段，**逻辑图里根本不存在脉动**，截了也白截。

必须用**系统级屏幕截图**，截下显示器上真实显示的画面：

- Windows：`Win + Shift + S`（区域截图）或 `Win + G` 游戏栏，`Snipaste` / `ShareX` 也行
- 或手机拍屏（不如截图精确，但看整体观感够用）

截图要包含一小块**网格密集区**（房屋墙面/田块/路面），格线越密越容易看出脉动。

## 2. 验收步骤

### 准备

用 Steam 版 Godot 打开项目，正常运行游戏（非 headless）：

```
D:\steam\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe
```

显示器分别切到 **1920×1080**（重点）、2560×1440、3840×2160。
游戏内按 `F11`（或 `Alt+Enter`）切**全屏独占**（Exclusive Fullscreen）——这是缩放最纯粹的档位。

### 每档检查三项

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | **静止观感**：站在原地看房屋墙面和田块 | 格线清晰、像素块边缘锐利、**没有发糊/半透明** |
| 2 | **滚动脉动**（仅 1080p 重点）：按住 WASD 缓慢横向移动，盯住一条竖直格线 | 没有明显的**粗细跳动 / 毛刺感 / 呼吸感** |
| 3 | **HUD 文字**：顶部年份、底部提示字 | 20px 字在 1.5× 下约 30px 物理高，锯齿可容忍，但**不能糊成一团或重叠** |

### 采样建议

1080p 那档，截 **2 张**：静止一张 + 滚动中一张。
两张对比看同一条格线的宽度有没有变。

## 3. 判定 gate（明确标准）

### ✅ 通过 → 开美术线

- 静止画面锐利不糊（三项里的 #1、#3 必过）
- 滚动脉动**基本无感**，或只有凑很近才看得出 1px 抖动，不影响正常游玩

→ 维持 `scale_mode=0`，我会把结论回写进 `house-spec.md` / `HANDOFF.md`，然后开美术线。

### ❌ 不通过 → 回退整数倍 2a

只要**正常游玩距离下滚动脉动明显烦人**，就回退，不走"忍一忍"路线。

回退清单（`scale_mode=1`，视口 640×360，窗口 1280×720）：

| 文件 | 改动 |
|---|---|
| `project.godot:20-25` | viewport 1280×720 → 640×360；`scale_mode=0` → `1` |
| `scripts/camera_rig.gd:16` | `VIEWPORT := Vector2(1280, 720)` → `(640, 360)` |
| `scripts/hud.gd` | UI 倍率 2.0 → 1.0，字号 20/26 → 10/13，所有按 UI 写的坐标减半 |
| `_mdtest/display_check.gd` | 期望值 `(1280,720)`/`fractional` → `(640,360)`/`integer` |
| `_mdtest/hud_layout_check.gd` | 整份重排回 UI=1.0 |
| `_mdtest/camera_check.gd` | 期望视口改回 640×360 |

代价：**视野从 40×22.5 格减半到 20×11.25 格**（等于星露谷），28 格宽的 shen_a3 一屏放不下，镜头要贴紧跟随。HUD 要重排一次。这是为了"绝对不糊"付出的代价。
