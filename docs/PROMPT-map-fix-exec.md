### 引擎红线（违反会静默出错，必须懂）

| 红线 | 后果 |
|---|---|
| **竖路绝不能写 `road:true` 的 rect** | `world_view.gd:268-296` `_scene_bboxes()` 会把同帧所有 `road:true` 的 rect 用 `Rect2.merge` 合成**一个外包矩形**，`_draw_back` 整帧只贴一次路面。加一条 road:true 竖路 ⇒ 路口四周空地整片刷成柏油。A5 的竖路已经用 `polygon` + `label:"路"` + `solid:false` 写好了，照抄。 |
| **每帧只能有一个 `label:""` 的 rect** | `label==""` 的 rect 会进 field bbox（田图按 bbox 贴一次）。多于一个 ⇒ 两者合并成一块超大的田。 |
| **`label` 非空的 rect 在背景层被 `pass` 掉** | `world_view.gd:230` `elif label != "": pass` ⇒ 不进背景层，也不并入 `_scene_bboxes`。它靠前景层单独画（`_draw_prop`）。**label 非空 ≠ 看不见**，但要知道自己走的是哪条路。 |
| **`label` 决定贴图** | `world_view.gd:619-626`：含「槐」→ tree 贴图、含「井」→ well 贴图、含「碑」→ stele 贴图。**界碑的 label 必须含「碑」字**，改名会掉贴图。 |
| **界碑 rect 尺寸 ≠ 贴图画布尺寸** | 界碑 rect 一直是 **16×32（半个格宽）**，而界碑贴图画布是 **32×32（1 格见方）**。渲染层要把贴图按「底部中心锚点、1:1 不拉伸」画进 32×32 的框里（和树/井同一套 `_prop_box` 逻辑）。**引擎现在的 rect 分支会把贴图直接拉伸到 rect 尺寸（`world_view.gd:605-615`）⇒ 16×32 的 rect 配 32×32 的图会被压扁**。这条由「资产接线线」修，**本线只管数据**：rect 尺寸维持 16×32、热点写在「石头中心」，别自己去把 rect 改成 32×32（那会改碰撞与旧帧）。 |
