### 4. 所以美术的直觉是对的，但原因不是「房子小」

| | 星露谷农舍 | 我们陆家 |
|---|---|---|
| 外观 | 9×5 格 | **20×10 格** |
| 相对主角宽 | 主角的 9 倍 | 主角的 **20 倍** |
| 相对主角高 | 主角的 2.5 倍 | 主角的 **5 倍** |

**我们的房子绝对值比星露谷大得多**（20×10 vs 9×5，面积差 4.4 倍）。

那为什么美术觉得小？三个可能原因，需要讨论判断：

1. **房子是"占地"不是"视觉体量"**：20×10 里有一大半是院子（`lot` 含院子，屋本体只有 15×8），而渲染时院子和房子都是**同一种平铺色块**，看不出"这是一栋房子"
2. **没有高度**：星露谷的房子是伪 3D，有屋顶 + 墙面立面，5 格高的外观画出来是个"立起来的房子"；我们只有 16px 的平铺墙块，10 格高的占地画出来是个"趴在地上的色块"——**同样占地，观感差 3 倍**
3. **视口太小**：内部分辨率 640×360，一栋 20 格宽的房子（320px）占掉半个屏幕宽

## 必须守住的硬约束（这条最重要）

`house-spec.md` §0.1 定的：**内外严格 1:1**

> 玩家站在 1926 的空地按 Shift，人出现在 1951 那栋房子**内部**——不需要找门，**时间是门**。
> 外观占地必须精确等于内部可行走区 + 墙厚。**差一格，切时间就卡墙里。**

这是整个游戏的**核心机制**（主题就是"时间是门"），**不能学星露谷的"内部比外部大"**（`house-spec.md` §0.2 里明确写了"不学"）。

**所以：不能靠"把内部做大"来解决观感问题。**

## 要讨论并给出结论的问题

### 1. 到底该调什么（核心问题）

现在有四个可动的量，请判断哪个（或哪几个组合）是正解：

- **A. 把房子的 lot 缩小**（比如陆家 20×10 → 14×7），让房子相对村子更小、更"像民居"
  - 代价：屋里放不下现有的家具（陆家 12 件、沈家 A3 有 51 件），要么砍家具要么砍房间
- **B. 房子保持占地不变，靠伪 3D 立起来**（屋顶+立面），视觉体量自然变大
  - 代价：需要伪 3D 渲染改造（另一条线在讨论，见 `docs/PROMPT-pseudo3d.md`）
- **C. 改格子基准**：一格从 16px 改成 24 或 32px（主角跟着改成 1×2 格但更大）
  - 代价：**所有已定的坐标全废**，`frames.json`、16 栋 house 数据、世界尺寸全要重算
- **D. 只改视口**：内部分辨率从 640×360 降到 480×270 或 512×288，让同样的房子在屏幕上显得更大
  - 代价：视野变小，一屏看不全村子；像素画在非整数倍缩放下会糊

**请给出明确推荐 + 理由，不要罗列完就完事。**

### 2. 如果缩小房子，家具怎么办

这是最硬的约束冲突。现状：

- `shen_a3`（沈家 1976 凹形）占地 28×21，屋本体 28×12，塞了 **51 件家具**
- `lu_house` 占地 20×10，屋本体 15×8，塞了 12 件
- `house-spec.md` §4.6.2 定的**家具九档最小 1×1**（16×16px），因为"格子再小就点不中"

如果房子要缩小，是：
- 砍家具数量？
- 砍房间数量（A3 现在 7 个房间）？
- 还是承认"穷人家的房就是小、家具就是少"（这本身是叙事——陆家是佃农）？

**注意**：家具是**检视点来源**（`furniture[].clue` 决定玩家能查到什么）。砍家具 = 砍线索。这条要单独评估。

### 3. 星露谷的"内部比外部大"到底怎么绕开的

星露谷农舍外观 9×5、内部 10×7，是靠"进门 warp 换地图 + 内部独立坐标系"实现的（`house-spec.md` §8.1 提过）。

我们**不能**这么做（会把"时间是门"砸掉）。但要想清楚一件事：

**在"内外 1:1"前提下，房子里能站人的空间有多少？**

- 屋本体 15×8 格，减去四面墙（每边 1 格）→ **13×6 = 78 格可行走**
- 主角占 1×2 格 → 理论上能放 78 件 1×1 家具（实际要留走道）
- 对比星露谷农舍内部 10×7 → 减墙后约 8×5 = 40 格

**我们的单栋房子其实比星露谷农舍内部还大**。这个数据能不能说服美术？

### 4. 美术交付规格要怎么定

现在 `assets/village/` 是**空的**（零张成品图）。要趁这次把交付规格定死：

- 一栋房子的图怎么切？
  - 方案①：整体一张 PNG（含屋顶，进屋时整张淡出）—— 简单，但进屋就看不见房子了
  - 方案②：`base`（地板+墙内侧）+ `roof`（屋顶）+ `props`（家具）三层 —— `house-spec.md` §4.5.1 已定这个方向
  - 方案③：屋顶 / 墙立面 / 地板 / 家具 四层以上
- 画布尺寸怎么算？按 lot（含院子）还是屋本体？
- 锚点：`house-spec.md` §5 定的是「底部中心」——lot 的底部中心还是屋本体的底部中心？

### 5. 和伪 3D 改造的先后关系

`docs/PROMPT-pseudo3d.md` 里在讨论渲染架构改造（y-sort、屋顶淡出、墙立面）。

**尺寸调整和伪 3D 改造，哪个先做？**
- 如果先改尺寸，伪 3D 方案要基于新尺寸设计
- 如果先做伪 3D，尺寸可能在立起来后发现"其实不用调"

这个顺序问题是当前最实际的决策，请给建议。
