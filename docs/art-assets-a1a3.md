## 2. 交付规范（硬要求，不满足会掉图或错位）

| 项 | 要求 |
|---|---|
| 网格 | 1 格 = **32×32 px**；家具只用九档：1×1、1×2、1×3、2×1、2×2、2×3、3×1、3×2、3×3 |
| 画布 | **外观 = 占地宽 × (占地高 + 32)px**（高度比占地多一格，多出的一格在顶部，是墙与屋顶立起来的高度）；家具 = 占地格数 × 32px（**允许高度多画一格**做朝向立面，但占地按数据算，不看 PNG 像素） |
| 锚点 | 一律**底部中心**（外观的画布底边仍与占地底边对齐，只是往上多一格） |
| 透明边 | 每张图四周留 **2px** 透明，别让像素贴边 |
| base / roof | **同宽同高同锚点**，高度都是 `占地高 + 32`；玩家走进占地矩形时 `roof` 整层淡出、`base` 留在原地 |
| 文件名 | **禁改**。数据按文件名对号入座，改名等于丢图 |
| 缺图兜底 | 代码对缺图有回落：返回 null → 画纯色块 + id 名，游戏不崩。所以可以分批进图 |

为什么外观不做 32px 瓦片拼：檐口厚度、屋顶坡度、烟囱、门窗凹陷、墙脚水渍这些在 32px 瓦片里要么拼不出来、要么网格重复一眼露怯；而且 A1–A3 每帧房型本来就不一样（一字 → L 形 → 凹形 → 废墟），外观无论如何都要重画，「瓦片换色省工」在这里不成立。星露谷也是这么分的：建筑外观整栋单图，室内家具按格吸附。

### 5.5 画家具的五个坑

1. **高度可以多画一格**：星露谷那套画法会画出朝向观众的立面，所以 1×1 的凳子源图常常是 32×64。**占地按数据算，不看 PNG 像素**。—— 这条和外观层的「+32px」是同一个道理：所有立体物都按 `(x, y − 高度)` 绘制，立面一律往上长。
2. **锚点底部中心**：多出来的那一格往**上**长，不要往左右偏。
3. **不要画地板 / 墙体**：家具图只含物件本身，底下的地板墙由 `base` 层出，否则叠两层会脏。
4. **院子建筑（茅房 3×2）里还嵌了茅坑**：两件是分开的两个文件，茅房只画外壳和门，坑单独一层。
5. **立面不要画细节**：2× 整数缩放下**一格只有星露谷 1/4 的像素**，砖缝 / 木纹 / 窗框会糊成噪点。只靠色阶分层：墙顶亮带 + 墙身 + 墙基暗带。外观层同理。

## 9. 与既有规范的差异（需要同步给美术）
