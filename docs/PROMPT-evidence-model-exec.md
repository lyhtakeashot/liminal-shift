## §1 为什么改（现状的问题）

现在的证物模型是「**按对象去重，但对象键不稳定**」：

- 世界地标的 key ＝ hotspot 的 `title`（`scripts/main.gd:249-269`）；家具的 key ＝ `house_id::家具名`。
- 而 **title 会随年代变**：「老井」/「老井 · 石板」/「老井 · 三层水泥」/「老井 · 沥青补丁」是四个不同的 key ⇒ 同一口井在档案里散成四条，玩家看不出它们是同一口井。
- **house_id 也会随年代变**：`mill_a1` / `mill_a2` / `mill_a3` 是同一栋磨坊（磨坊 → 粮站），却是三个 key ⇒ 磨坊的账桌散成三条。
- 反过来，同 key 跨年代又**只留首次那条**：老槐五帧 title 都是「老槐」⇒ 玩家 2026 再看一次，档案里那条永远停在 1926 的「今年刚栽下」，1951 歪了、1976 露根、2026 一百岁全被丢掉。

**这游戏的全部主题就是「同一个东西在五个年代里的变化」**，而证物档案是主角唯一的跨时代记录板（`docs/story.md:19-26`：他是归档员，职责是如实记录；结局是「第七十二万三千零一卷」）。

### §1.1 拍板的结构（2026-11-23 用户拍板）

> **一件物件 = 一张卡；卡内按年代追加观察记录。**

不是「一对象一年一张卡」（那样档案会变成按年份排序的流水账，像数据库不像卷宗）。

档案该长这样：

```
老槐                                            1926 · 2026
  1926  1926 · 村中   老槐树，今年刚栽下。树干还细，根边堆着新土。
  1951  1951 · 村中   二十五岁。树开始朝远离井的方向歪过去。
  1976  1976 · 村中   四十九岁。树干朝西北歪出去，树根有一半露在土外面。
  2001  2001 · 村中   七十五岁。树根一侧新抹了水泥，抹到一半，露出来的根又给围了回去。
  2026  2026 · 村中   一百岁。树根拱起来，把旁边超市墙根的地砖顶裂了。
```

界碑同理，一张卡里三次挪位自己排好：

```
界碑                                            1926 · 2026
  1926  半截石碑，埋在路边的土里。字被凿过，只剩两个：「周界」。
  2001  石头下缘被新土埋深了一截。
  2026  围墙里嵌着半截石碑，碑面和砖面抹成了一个平……
```

## §2 必改清单（4 件事）

### 2.1 归一后的 key（一张卡一把钥匙）

key ＝ **物件身份**，不含年代。两条归一规则：

**规则 A —— 家具：按「房屋族 + 家具名」**

同一栋房子在五个年代换了 id，但它是同一栋。房屋族对照表（**直接照抄这张表进代码**，写在 `scripts/main.gd` 里做成常量表）：

| 房屋 id | 族 |
|---|---|
| `lu_house` / `lu_a2` / `lu_a3` | `lu` |
| `shen_a1` / `shen_a2` / `shen_a3` / `shen_a4` | `shen` |
| `mill_a1` / `mill_a2` / `mill_a3` | `mill` |
| `zhou_house` / `zhou_a2` / `zhou_a3` / `zhou_a4` | `zhou` |
| `market` | `market` |
| `zheng_a4` | `zheng` |
| `school` | `school` |
| `toyshop` | `toyshop` |

家具 key ＝ `"<族>::<家具名>"`（用 `h.furniture` 原始家具名，**不是** title）。
例：`mill::老井`、`mill::账桌`、`shen::蜂窝煤炉`、`zhou::账桌`、`market::文件柜`。
⚠️ `zheng_a4` 虽然与陆家同址，但是另一户人家（story 明确「住户对陆家旧事一无所知」）⇒ 族不同、卡不同。
⚠️ 同族不同房间的同名家具是**不同的卡**（沈家的账桌 ≠ 周家的账桌），因为族不同。

**规则 B —— 世界地标：按「· 之前的主体名」**

地标 title 形如「老井 · 石板」——「·」后面是**状态**，前面才是**物件**。
地标 key ＝ title 第一个「·」之前的部分（去首尾空白）；没有「·」就用整串。

| title | key |
|---|---|
| 老井 / 老井 · 石板 / 老井 · 三层水泥 / 老井 · 沥青补丁 | `老井` |
| 老槐 | `老槐` |
| 界碑 | `界碑` |
| 坝 | `坝` |
| 田 | `田` |
| 超市工地 · 南大门 | `超市工地` |
| 路口 · 红绿灯基座 | `路口` |
| 停车场 | `停车场` |

**规则 C —— 家具与地标是两个命名空间**：家具 key 带 `族::` 前缀，地标 key 不带 ⇒ 磨坊院里那口井（`mill::老井`，显示名「磨坊 · 院里」）与村中那口老井（`老井`）**永远是两张卡**，这是有意保留的。

### 2.2 卡片结构：一张卡内多条观察

条目结构改成：

```
{
  "key":      "老槐",              # 归一键（§2.1）
  "name":     "老槐",              # 显示名 ＝ 首次收集时的 hotspot title（不随年代改写）
  "order":    0,                   # 收集次序（卡片排序用）
  "observations": [                # 按收集顺序追加
    { "year": 1926, "title": "老槐", "source": "1926 · 村中", "text": "……" },
    { "year": 1951, "title": "老槐", "source": "1951 · 村中", "text": "……" },
    …
  ]
}
```

收集规则（`try_collect` 改成返回三态，别只返回 bool）：

| 情况 | 行为 | 返回 |
|---|---|---|
| key 首次出现 | 建卡 + 追加第 1 条观察 | 新建卡 |
| key 已存在、**同年代**已记过 | **什么都不做**（不追加、不改顺序） | 重复（去重） |
| key 已存在、**是新年份** | 在该卡 `observations` 末尾追加一条 | 追加观察 |

- `source` 写法不变（`%d · 村中` / `%s · %d` 房子名+年份，`scripts/main.gd:260`/`:264`）。
- 卡片 `name` ＝ **首次**收集时的 title；后续年代追加不改卡片名（一张卡一个名字）。
- 每条观察保留自己的 `title`（如「老井 · 石板」）——那是那个年代的物件状态，是观察的一部分，别丢。

### 2.3 界面：一行一张卡，详情页按年排

`scripts/evidence_archive.gd` 要改成：

- **列表页**：一行 = 一张卡（不是一条观察）。显示：卡片名 + 右侧来源/年份跨度（如 `1926 · 2026`）+ 一行摘要（**首条观察**的文本摘要，不是拼接）。条目数显示从「已收集 N 件」改成「已收集 N 件 · M 条观察」之类（N=卡数，M=观察条数；具体文案你定，但要两个数字都在）。
- **详情页**：卡片名 + 「已记录 N 次观察」+ **按年代顺序**列出每条观察（年份 · 来源标签 + 该条文案）。年代顺序＝升序（1926→2026）；若玩家不是按年代顺序收集的，仍按年代排，**同年代多条按收集顺序**。
- 详情页要能滚动（现有 `scroll` 机制可复用，`_draw_detail` 现在是单段文本）。
- 「新」角标语义：现在指「上次关档以来新收集的件数」（`evidence_archive.gd` 的 `new_count`）。改成：**新增卡数 + 新增观察数**都算「新」（同一张卡追加一条新年代也算新）。具体实现你定，但要在报告里说明口径。
- 底部 footer（`_draw_footer`，约 `:291`）加一行「**世界已暂停 · 按 I 或 Esc 关闭档案**」。
