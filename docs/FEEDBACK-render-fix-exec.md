## 1. 改了什么（只动 `scripts/world_view.gd`，188 插入 / 41 删除）

**§2.1 色块树冠不再上抬**：`_draw_prop()` 色块树分支删掉 `var lifted := center + offset + Vector2(0, -rad * 0.7)`，改为 `draw_circle(center + offset, rad, c)`，亮部同步平移，树干不动。理由：贴图分支（A1–A3 有 `tree_a1..a3.png`）本来就不上抬，色块上抬是历史补偿，结果 A4/A5（无树贴图、走色块）的老槐比贴图版高一截且更靠前，正好把旁边的老井盖死。

**§2.2 圆的深度键按「立着 / 贴地」分开**：`_collect_front()` 的 circle 分支由 `float(cp[1]) + rad * 0.7` 改为 `_circle_sort_y(sd)` —— 立着的树（label 含「槐」且 rad ≥ 12）取树冠底缘 `center.y + radius`；贴地圆盘（label 含「井」等）取圆盘底缘 `center.y + radius`。两支数值相同但**取值理由分开写**：以后树冠若恢复上抬，只改「立着」那一支。

**§2.3 井恒可见 + 永不挡玩家（就地补画）**：**没有**把井摘出排序链另开一层（会打乱 `sort_y` 单调性，也会改掉井与墙/家具的相对关系），**也没有**把补画放到整层末尾（会让井盖住南边的墙/屋顶/家具、玩家盖住南边的墙）。改为：① 第一遍照常按 `sort_y` 画全部，**排序链一个字没动**；② **补画 A**：某棵树画在井之后且树冠真的压住那口井 → 紧跟在这棵树之后把那口井再画一遍；③ **补画 B**：某口井真的盖住玩家 → 紧跟在这口井（它的最后一次画）之后把玩家再画一遍。只把「真重叠的那一对」往后挪一格 ⇒ 墙 / 屋顶 / 家具 / 门洞 / standing rect 的前后关系完全不受影响。

新增辅助：`_prop_kind()`（0 其他 / 1 贴地地标 / 2 立着的树）、`_player_over_well()`（玩家身体框 `Rect2(player_pos.x-16, player_pos.y-18, 32, 32)` 与井外接盒相交才算真挡）、`_draw_player()`、`_circle_bounds()`（色块树 = `crown.merge(trunk)`）、`_is_standing_tree()`、`_is_ground_landmark()`。
