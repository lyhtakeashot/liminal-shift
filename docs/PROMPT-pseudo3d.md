## 当前实现的真实状态（我核实过，别猜）

**游戏是纯 2D 俯视，没有任何伪 3D。** 具体表现：

1. **`world_view.gd` 是 `Control` 节点，所有东西在一个 `_draw()` 里按 `shapes` 数组顺序平铺画**
   - 房子：`_draw_house()` 画 4 层矩形（lot 底色 → 房间色块 → 墙体 → 家具块）
   - 墙是**平铺的 16×16 方块**，没有高度、没有侧面
   - 没有 `z_index`、没有逐对象排序、没有 y-sort

2. **主角是几何图形**
   - `player.gd`：`draw_circle()` 画圆 + `draw_colored_polygon()` 画朝向三角
   - `z_index = 10`（固定值，不是按 y 动态算）
   - 站在房子前面永远盖住房子，站在房子后面也盖住——**没有遮挡关系**

3. **碰撞是纯数据**
   - `frame_data.gd` 的 `is_free()` 用 AABB 相交，只有 x/y，**没有高度 z 维度**
   - 这是刻意的（`HANDOFF.md` §3.3/§3.4：绕开 `visible=false` 不关碰撞的坑）

4. **世界 1600×900，一格 16px**，`project.godot` 用 `gl_compatibility` + Nearest 过滤 + 整数倍缩放

5. **房子已经设计成俯视 3/4 的规格**（`house-spec.md` §4.5.2）：
   - 北墙/西墙画全高内侧面（可见）
   - 东墙/南墙只画矮内侧面
   - 但**这只是文档里的设计，代码没实现**

## 要解决的核心矛盾

用户原话：**「建筑、人物应该都是伪 3D 的吧」**。

现在的状态是「一张俯视平面图上堆色块」，看起来像地图编辑器，不像游戏。要做到：

- 房子有**屋顶**（从上看得到屋面）+ **墙的立面**（侧面看得见，体现高度）
- 人物站在房子**南边**要挡住房子，站在**北边**要被房子挡住
- 树有**树干 + 树冠**的层次，不是地上的一个绿圆
- 家具在屋里时，玩家能绕到桌子**后面**（被遮挡）

**同时不能破坏的两条硬约束**：
1. **内外严格 1:1**（`house-spec.md` §0.1）——外观占地必须精确等于内部可行走区 + 墙厚。差一格，切时间就卡墙里。**这是整个游戏的核心机制，不能为了伪 3D 让步。**
2. **碰撞纯数据、不引物理**（`HANDOFF.md` §3.3/§3.4）——`visible=false` 不关碰撞、目标帧未实例化也要能做重叠检测。所以不能改成「每个物体挂 CollisionShape2D」。

## 要讨论并给出结论的问题

### 1. 架构选型（最重要）

现在所有东西在一个 `Control._draw()` 里画。伪 3D 需要**逐对象排序**（y-sort），这在单 `_draw()` 里做不到（`draw_*` 调用顺序 = 绘制顺序，但没法在同一个函数里插入「按 y 排序的通用对象」）。

三条路，请对比后给推荐：

- **A. 全改成 Node2D 子节点**：每个房子/树/家具一个 `Node2D`，靠 `z_index` 或 `y_sort_enabled` 排序。代价：`frames.json` 数据驱动要变成运行时建节点，切帧要重建/隐藏节点。
- **B. 保留单 `_draw()`，自己排序**：在 `_draw()` 里先收集所有「可排序对象」（房子块、树、玩家…），按 `sort_key = y + height` 排好，再顺序 `draw_*`。玩家也得从 `Node2D` 挪进这个排序里。代价：`player.gd` 要并入 `world_view`，或者用 `CanvasItem` 的子节点 + `draw` 回调转换。
- **C. 混合**：场景层（地面/河/路/田）留在单一 `_draw()` 里批量画（它们不需要排序），「立体对象」（房子、树、家具、玩家）用独立 `Node2D` + `y_sort_enabled`。

**判断依据**：切帧时（时间轴推一年）要整帧换数据，哪种方案换得干净、不留残影、不重复建节点？

### 2. 屋顶与墙立面怎么画

- 屋顶是一个「比占地略大的矩形/多边形」，直接盖在房子 lot 上？
- 玩家进屋时屋顶要淡出（`house-spec.md` §4.5.1 说按「玩家进入占地矩形」判定）——淡出用 `modulate.a` 还是换一张图？
- 墙的立面：北墙/西墙画全高（比如向上延伸 8~16px），东墙/南墙画矮的。这个「向上延伸」是纯视觉（不影响碰撞），还是要在数据里加 `height` 字段？

**注意**：现在的房子是 `house_shape.gd` 从墙角格矩阵实时画的色块。加立面意味着「同一格墙」要画两次（地面投影 + 竖直立面），数据上怎么表达？

### 3. 玩家怎么融入

现在 `player.gd` 是独立 `Node2D`、`z_index=10` 固定。伪 3D 要求它参与 y 排序：

- 站房子南边（y 大）→ 玩家挡住房子
- 站房子北边（y 小）→ 房子挡住玩家

如果选方案 B，玩家得从 `Node2D` 变成「排序表里的一项」，`player.gd` 的绘制怎么保留（它有残影、朝向三角、走路摆动）？

### 4. 逐帧切换怎么保证不穿帮

时间轴推帧时，整帧数据换。伪 3D 对象的**高度**要不要也逐帧变？

- A1 磨坊是土坯矮房，A3 粮站是高仓——高度不同的话，屋顶位置、墙立面的高度都不同
- 如果高度逐帧变，`frames.json` 的 house shape 里要不要加 `roof_height` / `wall_height` 字段？还是从 `houses_data.json` 的房子类型推？

### 5. 性能与美术交付

- 世界 1600×900，一帧有 4 栋房 + 若干家具，改成逐对象后节点数量级多少？切帧时重建节点的开销？
- **美术还没有一张成品图**（`assets/village/` 是空的）。伪 3D 的图怎么切？屋顶一张、墙立面一张、地板一张？还是整体一张带透明？
  - `world_view.gd` 现在有 `_house_tex()` 会尝试 `load("res://assets/village/<id>.png")`，有图就画图、没图就画色块。这个降级逻辑要保留。

### 6. 是否要动碰撞

**默认不动。** 但要说清楚：

- 伪 3D 的「墙高」会不会让人产生「我能跳上去/爬过去」的误解？如果会，要不要视觉上做提示（比如墙顶高光、影子）？
- `house-spec.md` §8 提到过「楼层/表面高度快照」方案（降级到 P3）。这次伪 3D 改造要不要顺手把 z 维度做进去，还是**先只做视觉、碰撞仍是纯 2D**？
