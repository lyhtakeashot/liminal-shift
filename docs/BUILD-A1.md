## §3 内部数据从哪来

`_ref/houses/houses_data.json` 是 18 栋房子的唯一真相源，里面每栋有：

```jsonc
{
  "id": "lu_house",
  "lot": [0, 0, 19, 9],            // 占地（含院子），格坐标
  "wings": [[0, 0, 15, 8]],        // 屋本体，格坐标含墙
  "partitions": [[6,1,6,5], ...],  // 内部隔墙，x1,y1,x2,y2（沿轴的一段）
  "doors": [[6,7], ...],           // 门洞（墙上的缺口）
  "gate": [[6,7]],                 // 院门
  "rooms": [["夫妻房", 1,1,4,6, "bed"], ...],  // 房间矩形 + 配色 key
  "furniture": [ { "name": "双人床", "rect": [1,1,2,2], "clue": false, ... } ]
}
```

**格 → 像素**：`px = 世界原点 + 格坐标 × 16`。

生成器 `_ref/houses/gen_all_houses.py` 里已经有一套完整逻辑：从 `wings` 推出墙体网格（`build_grid()`），`partitions` 盖上去，`doors` 挖空。**GDScript 那边照抄这个算法，不要重新发明。**

关键规则（已在 `gen_all_houses.py` 验证过）：
- 墙 = 「四邻有室内格」的格子，所以**墙角天然缺一格**，不用特殊处理
- 两翼相接处墙体自动消解，两翼互通，不用开门洞
- 门必须是墙上的格子，挖掉后成为通路
- 房间矩形**不含墙**（这是硬规则，`check_all()` 会断言）

`pos` = lot 左上角在世界里的像素坐标；`id` 指向 `houses_data.json`。

### 4.2 新脚本 `scripts/house_shape.gd`

职责：给一个 `id` + 世界坐标，吐出渲染要用的东西。

```
house_shape.gd
  static func load_all() -> Dictionary      # 读 houses_data.json，缓存
  static func grid_of(data) -> Array        # 抄 build_grid()，出 '#'/'.'/'D'/'G' 网格
  static func solid_rects(data, pos) -> Array   # 墙 → 世界坐标 Rect2 列表
  static func hotspots(data, pos) -> Array      # furniture 里 clue=true 的 → 检视点
```

**不要引 physics**。碰撞继续走 `scripts/frame_data.gd:64` 的 `is_free()` 纯 AABB。

⚠️ **`houses_data.json` 在 `_ref/` 下，不在 `res://` 能直接 `load()` 的位置**。三个办法，选一个：

| 办法 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | `FileAccess.open("res://_ref/houses/houses_data.json")`，并把 `_ref/houses/houses_data.json` 加进导出白名单 | 导出时要记得配；但只有一处真相源 |
| B | 构建时用 `gen_all_houses.py` 生成一份 `data/houses.json` 到 `res://` 下 | 两份文件，可能不同步 |
| C | 手抄 JSON 字符串进 `.gd` 常量 | 改一次要抄一次，别用 |

现在还没配 Web 导出（P3），A 最省事。真到导出那天，在 `export_presets.cfg` 的 `include_filter` 里加 `_ref/houses/houses_data.json` 就行。

### 4.3 `scripts/frame_data.gd`

`setup()` 里加一个分支：

```gdscript
match String(sd.get("type", "")):
    "rect":   solid_rects.append(_rect_from(sd))
    "circle": ...
    "house":  solid_rects.append_array(HouseShape.solid_rects(...))
```

⚠️ 注意：`solid_rects` 现在只存**外轮廓**。房子的墙是**内部隔墙**，外轮廓要 S 型——如果直接把整个 lot 做成一个矩形，玩家就进不去了。

**推荐做法**：把房子内部画出来的墙，逐段变成 `Rect2`。门洞处不留矩形。**lot 边界本身不做阻挡**（院墙另说，A1 的院墙在 `houses_data.json` 之外，需要单独加 rect）。

### 4.4 `scripts/world_view.gd`

`_draw_shapes()` 加 `"house"` 分支，画四层：

1. **lot 底色**（院子 + 地面）
2. **房间色块**（按 `rooms` 的 key 取 `houses_data.json` 里的配色）
3. **墙体**（棕色块；门洞留空）
4. **家具占位块** + 名字（`furniture[].rect`）

美术接进来以后，第 2–4 层换成贴图，第 1 层保留。

## §5 检视点怎么摆

A1 现在是 4 条手写的检视点。这一轮改成「**手写的地标 + 自动生成的家具有线索**」两拨：

| 来源 | 例子 |
|---|---|
| 手写（`frames.json` 的 `hotspots`） | 老井、田、坝、界碑 |
| 自动（`houses_data.json` 的 `furniture[].clue: true`） | 磨坊账桌（假《水簿》）、陆家旧木箱、周家小桌 |

自动生成时，检视点落在**家具矩形中心**，`reach` 用默认 34。

⚠️ **A1 的磨坊没有暗龛**（`docs/house-spec.md` §4.7 已定：暗龛 A2 才砌）。所以：

- `mill_a1` 里 `clue: true` 的应该是**账桌**（摆着假《水簿》）
- 石磨也 `clue: true`，但读的是「磨盘上的字」
- **A1 不该出现任何指向暗龛的检视文本**

## §6 占位块：美术没图也要能跑

用户已定（"美术只画图，数据匹配由我们做，图太多只能一批批放入"）：

```
有图 → 画图
无图 → 画色块 + 名字（不许崩、不许空白）
```

所以 `house_shape.gd` 的取图逻辑必须是：

```gdscript
var tex := load("res://assets/village/%s.png" % id)   # 拿不到 load 返回 null
if tex != null:
    draw_texture(...)
else:
    draw_rect(Rect2(...), placeholder_color)
    draw_string(..., id)
```

`load()` 拿到 null 不报错、直接画色块。**这是硬要求**——美术一批批进图时，游戏必须一直能跑。

| 一次改太多 | 先把 A1 搭通，再谈 A2–A5、起始帧反转、楼层 |
| 改完不跑 | 改坐标 → 跑 `_layout_check.py` → 跑 `greybox_check.gd` → 看图，**三步缺一不可** |
| pwsh 权限 | 所有 `pwsh` 调用都要申请「完全权限」（这个目录缺 `WRITE_DAC`，只影响启动命令，不影响读写文件） |
| `gate` 不等于临街口 | 门先通到院子，院子南沿才是外墙。院子那几行也是可走地面 |
| `safe_top` / `safe_bottom` | 见上表末行——没人读，别当坐标用 |
