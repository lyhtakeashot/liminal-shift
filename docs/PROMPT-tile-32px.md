## 三个可选方向（必须先选一个再动手）

「16 → 32」这句话有三种截然不同的解释，代价差十倍：

### 方案 1：格子变大，世界格数减少（画面构图不变）

- 一格 16 → **32px**，世界仍是 **1600×900px**，但变成 **50×28 格**
- 主角变成 32×64px（占 1×2 格）
- **代价**：视口 640×360 里只能看到 20×11 格（原来 40×22.5），**视野缩小一半**；26 格宽的沈家 A3 会占满整个屏幕
- **房子数据要全部除以 2**（`houses_data.json` 的 lot/wings/rooms/furniture 坐标）

### 方案 2：格子变大，世界同比放大（视野构图不变）

- 一格 16 → **32px**，世界 **1600×900 → 3200×1800px**，格数保持 100×56
- 主角 32×64px
- 视口 640×360 里看到 20×11 格 —— 和方案 1 一样是"看得更少"
- **代价**：世界要翻倍，房子坐标数值要乘 2；`data/frames.json` 里所有像素坐标重算

### 方案 3：不动坐标，只提高美术交付精度（真正的"提高精度"）

- 一格的世界坐标仍是 16px，**但美术按 32px 的像素密度画图**
- 渲染时用 `draw_texture_rect` 等比缩放（整数倍 2x）
- **代价**：不需要改任何坐标；但"像素风"的颗粒感会变成 16px 逻辑 + 32px 贴图（星露谷 1.6 的 HD 纹理就是类似做法）
- ⚠️ **关键风险**：Nearest 过滤下，非整数倍缩放会糊；而且"精度提高"只在美术图上有意义，程序逻辑完全不变

**请先判断：美术说的"提高精度"到底是哪一种？** 如果是"觉得 16px 画不出细节"，那方案 3 就够；如果是"想让人物/房子在画面里更大"，那是方案 1/2。

## 必须守住的硬约束

### 1. 内外严格 1:1（`house-spec.md` §0.1）

> 玩家站在 1926 的空地按 Shift，人出现在 1951 那栋房子**内部**——不需要找门，**时间是门**。
> 外观占地必须精确等于内部可行走区 + 墙厚。**差一格，切时间就卡墙里。**

改格子单位时，**房子的 lot 格数和内外比例都不能变**，只有"一格多少像素"变。

### 2. 碰撞是纯数据 AABB（`HANDOFF.md` §3.3/§3.4）

不建 `CollisionShape2D`。改格子单位时 `CHAR_RADIUS` 要同比缩放：
- 16px/格 → 半径 7
- 32px/格 → 半径 14

### 3. 整数倍缩放（`project.godot` 的 `scale_mode=1`）

像素画必须整数倍放大，否则糊。改单位时要想清楚：
- 内部分辨率还是 640×360 吗？
- 窗口 1280×720 还是 2 倍吗？
- 如果内部分辨率也要改（比如 1280×720），那窗口默认要变 2560×1440（很多笔记本跑不动）
