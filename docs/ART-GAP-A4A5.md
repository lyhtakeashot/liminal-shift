## 1 这是什么、这次要什么

《阈限迁移 SHIFT》是一款 **2D 俯视视角**的像素叙事游戏：主角在同一座村庄的
1926 / 1951 / 1976 / 2001 / 2026 五个时代之间来回切换，收集证物、追一桩跨四代人的旧案。
地图是一整张俯视图（不是等距、不是侧视），**一格 = 32×32 px**。

1926–1976 三帧的资产基本齐了，**这次要的是 2001 与 2026 两个时代还缺的全部美术**，
外加给 1926–1976 三帧补「空旷感」的几类新元素：

| 组 | 内容 | 张数 | 交到哪个目录 |
|---|---|---|---|
| A 组 | 六栋房子的屋体（base + roof） | **14** | `assets/village/houses/<族目录>/` |
| B 组 | 场景元素（河/路/田/地面/井/老槐/界碑） | **19** | `assets/village/scene/` |
| C 组 | 十字路口环岛的可复用零件 | **3** | `assets/village/scene/` |
| D 组 | 新增填充元素（山/路标/田地细分，给 1926–1976 用） | **26** | `assets/village/scene/` |
| E 组 | 家具（158 张缺口 + 2 张线索件重画） | **160** | `assets/village/props/` |
| **合计** | | **222** | |

> 🟢 **2026-11-25 更新：这次的重点是「复用」，不是「多设计」。**
> 地图的世界尺寸要放大（从 3200×2400 放大到约 4800×3600），但**所有会铺满地面的素材
> （河/路/田/地面/环岛）都改成 32×32 的单方格瓦**，引擎负责平铺/拼接。
> 也就是说：**这些素材的画布尺寸与地图最终多大无关**，一张 32×32 的瓦能铺到任何尺寸。
> 以后地图再放大，**这些图一张都不用重画**。请按「一张图到处用」的方式画，不要按固定长度的整帧图画。

进度用同目录的 `ART-GAP-A4A5.csv` 记（Excel 直接打开）：每张图一行，画完把「状态」改成「已完成」、
填上「负责人」和「完成日期」就行。**批次从 P0 往 P4 做**，前面批次是后面批次的依赖。

## 2 硬规范（每条都别破）

| 项目 | 要求 |
|---|---|
| 一格 | **32×32 px**。所有尺寸都是 32 的倍数，出现非 32 倍数的边就说明画错了 |
| 屋体画布 | 占地宽×32 × (占地高×32 **+ 32**)。多出来的那一格在**顶部**（墙立起来的高度），底边与占地底边对齐 |
| 家具画布 | 占地宽×32 × (占地高×32 **+ 32**)。多出来的那一格在**顶部**，放「高过占地的东西」（椅背、柜顶、招牌、天线） |
| 锚点 | 屋体/家具/树/井/界碑/路标：**底边中心**（图的下沿 = 占地的下沿）。**平铺瓦例外**：河/路/田/地面/中心岛这些 32×32 瓦片没有锚点概念，四边无缝即可，贴哪里由地图数据决定 |
| 透明边 | 家具四角留 **2px** 透明；稀疏小件（树/井/碑/路标）周围的透明就是它的轮廓外留白，**不要把留白算进画布** |
| base / roof | 两组文件**同宽同高同锚点**。base 是墙身+地面（不含屋顶），roof 只有屋顶；交付时分开给两张，游戏会先贴 base 再把 roof 淡出 |
| 家具占地档位 | 以**清单里给的那一格占地为准**（主流是九档：1×1 / 1×2 / 2×1 / 1×3 / 3×1 / 2×2 / 2×3 / 3×2 / 3×3）。数据里有几件是四格长（黑板/讲台 4×1），照清单画，**别自己改成 3×1** |
| 文件名 | **禁改**。清单里写的就是最终文件名，一个字都不要动（大小写、下划线、像素尺寸后缀都一样） |
| 像素风 | 关掉抗锯齿/平滑缩放，硬边像素；同一时代内统一光源（光从左上来）和描边粗细 |
| 缺图不崩 | 没交到的图先留空，游戏回退成色块；**不要为了占位交半成品**（半成品会被当成正式图贴上去） |
| 世界尺寸 | **地图会放大到约 4800 × 3600（一格仍是 32 px，格子变大的是地图不是像素）**。因此**所有铺满地面的素材一律做成 32×32 的单方格瓦**——地图再放大也不用重画。旧的「河/路/田按整帧一张大图」的说法**已作废** |

## 8 F 组 · 接线提醒（**不是给美术的**，是给地图/接线线的）

这几件是「仓库里已经有图 / 或者数据已就位，但代码没接上」的问题，美术**不用画**：

1. **草地瓦片 3 张没接线**：`ground_a1_tiles.png` / `ground_a2_tiles.png` / `ground_a3_tiles.png` 已经在仓库里，
   但地面现在是纯色 `draw_rect`（`scripts/world_view.gd:164`），三张图全仓零消费点 ⇒ 要接线，不用重画。
2. **界碑五帧共用一张**：`stele.png` 挂的是 `SHARED_SCENE`（`scripts/asset_draw.gd:43-46`），五帧显示同一张。
   B 组新出的 `stele_a1..a5.png` 要改成按帧取图，并把 `SHARED_SCENE` 拆开。顺带：界碑 rect 是 16×32，图是 32×32，会被拉伸压扁。
3. **A4/A5 井/树/路/河/田全走色块**：`SCENE_FILES` 只有 a1/a2/a3（`scripts/asset_draw.gd:18-40`），
   B 组图交回来后要补 a4/a5 条目。竖路不再单独出图（已改为复用 `road_a5_tiles.png` 平铺）。
4. **A4/A5 屋体根本没有查表项**：`scripts/world_view.gd:603-608` 的 `FAMILY` 只到 a1–a3（lu/mill/shen/zhou）；
   A 组 14 张交回来**必须先补表**，否则 `_house_tex()` 压根不会去找这些文件，图交了也不显示。
5. **超市两态需要按帧取图**：`FAMILY` 是「房子 id → (族, 帧)」的**一 id 一值**映射，而超市在 A4/A5 两帧里**共用同一个 id `market`**
   （`_ref/houses/houses_data.json` 只有一条 `market`）。两个年代要显示不同的屋体图（工地 vs 营业），
   得把取图键改成 (id, 当前帧)，或在 FAMILY 里按帧查 —— 不改的话 `market/a4_base.png` 与 `market/a5_base.png` 只有一张会生效。
6. **世界放大 ⇒ 引擎要改成平铺**：现在 `scripts/world_view.gd:263` 把河贴图画布写死成 `Vector2(3200, 416)`，
   `_scene_bboxes()`（`:276-304`）又把同帧所有 road rect 合并成**一个外包矩形**贴整张路图。
   地图放大到 4800×3600 后这套贴法会拉长变形 ⇒ 要改成「按瓦片平铺/拼接」。
   顺带一个老限制：竖路**不能**写成 `road:true` 的 rect（会被并进路的外包矩形、把整片空地刷成柏油），
   竖路仍用 polygon（label「路」、`solid:false`）。
