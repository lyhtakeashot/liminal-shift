## §1. 一句话

一个被世界遗忘的侦探，在同一个村庄里走了五次，
把一件被四代人层层埋掉的案子，归档。

**玩法**：只能沿时间或空间其中一个轴移动，按 Shift 切换。

> **2026-11-19 用户修正**：原版这里写「固定一屏」，已作废。
> 现在**空间轴镜头跟随玩家、时间轴镜头锁定**，地图已放大到 3200×2400（已落地，见 `HANDOFF-VILLAGE.md` §7.4）。
> 「一屏」这个限制从来不是玩法核心 —— **核心是「同一时刻只能动一个轴」**。

## §2. 操作规范（核心）

### 2.1 三个键位

| 键 | 空间轴 | 时间轴 |
|---|---|---|
| **W** | 向上走 | **向未来**（下一帧） |
| **S** | 向下走 | **向过去**（上一帧） |
| **A / D** | 向左 / 右走 | **无作用** |
| **Shift** | 切到时间轴 | 切到空间轴 |

### 2.2 一句话概括

> **Shift 只做一件事：切换轴。**
> **切换之后，同一组方向键含义变了。**

**这是整个游戏唯一的机制。** 不要加跳跃，不要加攻击，不要加交互键以外的任何东西。

### 2.3 两种模式的区别

| | 空间轴（Space） | 时间轴（Time） |
|---|---|---|
| 角色 | **真的在走**，位置变化 | **原地走**，位置不变 |
| 世界 | 静止（当前帧冻结） | **流动**（帧在前进/后退） |
| 按键效果 | 移动 | 推进/回退时间 |
| 碰撞 | 当前帧的碰撞体 | **目标帧的碰撞体**（见 §3.3） |
| 画面 | 彩色、清晰、稳定 | 去饱和、角色是唯一有颜色的、轻微色差 |
| 边缘 | 无 | 暗角收紧 |
| 声音 | 正常干声 | 低频衰减、脚步声音高随速度变 |
| 时间轴 UI | 收起 | 展开，显示刻度 |

### 2.4 「角色走动但位置不变」

时间轴模式下，角色播放走路动画，**但坐标不动**，世界在他周围溶解。

**必须满足三个条件才成立**：
1. **镜头锁定**在切轴那一刻的视野（不是"永远不跟"，见下方修正）
2. 世界在动（帧在推进）
3. 角色身后**有残影拖尾**

否则玩家会以为操作失灵。

> **2026-11-19 用户修正**：原版这里写「镜头完全不动」，指的是时间轴内不动 —— 这条不变。
> 但**空间轴现在要跟镜头**。用户原话：「我打算在空间轴的时候，镜头跟随移动，时间轴镜头锁定」。
> 实现：`scripts/camera_rig.gd` —— `set_time_mode(true)` 时把当前 offset 冻进 `frozen_offset`，
> 整段时间轴模式都不再更新；切回空间轴立刻恢复跟随（`FOLLOW=9.0` 平滑）。
> 地图放大后（见 `HANDOFF-VILLAGE.md` §7.4）这条才会明显生效；当初 640×360 等于视口大小时镜头本来就锁死。
> 另：早期加的可见边界线已按用户要求删除，地图边缘改为 `timeline.gd:97` 的隐形墙。

### 2.5 输入处理骨架

```gdscript
enum Axis { SPACE, TIME }

var axis: Axis = Axis.SPACE
var frame: int = 0          # 当前帧索引
var frame_max: int = N - 1
var character_pos: Vector2  # 空间轴的位置，切到时间轴时冻结

func _unhandled_input(e: InputEvent) -> void:
	if e.is_action_pressed("shift_axis"):
		axis = Axis.TIME if axis == Axis.SPACE else Axis.SPACE
		_on_axis_changed()
		return

	if axis == Axis.SPACE:
		# 正常的 8 向 / 4 向移动
		pass
	else:
		# W/S 推时间，A/D 无作用
		if e.is_action_pressed("move_up"):
			_try_step_time(+1)
		elif e.is_action_pressed("move_down"):
			_try_step_time(-1)
```

**关键**：`W/S` 在两个轴里复用同一个 action。不要另建 `time_forward` / `time_back` action，
**复用 `move_up` / `move_down`**，语义靠 `axis` 状态分派。

### 2.6 需要在 Project Settings 里建的 action

| Action | 键 |
|---|---|
| `move_up` | W，↑ |
| `move_down` | S，↓ |
| `move_left` | A，← |
| `move_right` | D，→ |
| `shift_axis` | Shift |

**注意**：`shift_axis` 用 `is_action_pressed`，**不要用长按**。
早期讨论过「轻按跳 / 长按擦」，**已废弃**——现在 Shift 是纯粹的模式开关。

## §3. 时间系统

### 3.1 五帧

| 帧 | 年份 | 村子 | 案件 |
|---|---|---|---|
| **A1** | 1926 | 三房、弯路、两田、磨坊、井 | 陆文溺亡 |
| **A2** | 1951 | 陆家房空、老井封、新井在路另一头 | 陆敬之被推进井 |
| **A3** | 1976 | 路还弯、草长、农田半荒、磨坊改粮站 | 方师傅被封进地基 |
| **A4** | 2001 | 路开始取直、粮站拆、超市在建、农田全荒 | 改地质报告 |
| **A5** | 2026 | 笔直十字路口、超市、玩具店、小学 | 沈明远什么都不知道 |

**每代都是 36 岁**（隐线，归档表上五行连续 36 时会让人发毛）。
**唯一的例外是陆敬之——他死在 24 岁。** 沈守业 36，陆敬之 24：一个推，一个被推。
（这条差异是刻意的，2026-11-19 定的，见 `story.md` §3.1）

### 3.2 帧有两类

| 类型 | 数量 | 作用 | 成本 |
|---|---|---|---|
| **锚点帧** | 5（A1–A5） | 可探索的时间节点 | 高 |
| **过渡帧** | 每个间隔 4–5 张，共 ~20 | 让时间变化看起来自然 | 低（大量复用） |

**总计约 25 帧**，对上你说的 25~30。

**过渡帧本身就是内容**：有些线索只在过渡帧可见（比如 A3→A4 之间「地基挖开还没回填」的窗口）。
**否则玩家只会按一下 Shift 直接跳到目标年代，中间 20 张白做。**

### 3.3 碰撞：这是最大的坑（**已解决，这里只留结论**）

**`visible = false` 不会关闭碰撞。** 这是 Godot 的既定行为。

意味着：如果你靠切可见性来刷时间，**25 个帧的墙会同时生效**，
玩家会被 1926 年那堵早就拆掉的墙挡住。

> **⚠️ 下面这段是旧方案（`base.tscn` + `set_active()`），已经不用了。**
> 实际采用的是**纯数据方案**：不建任何 `CollisionShape2D`，
> 所有阻挡在 `frames.json` 里写成矩形，判定走 `frame_data.gd` 的 AABB 数学。
> **这个坑从根上绕开了，不需要再实现 `set_active()`。**
> 留在这里只是为了让接手的人知道「为什么当初不这么做」。

旧方案（作废）：

```gdscript
extends Node2D

func set_active(on: bool) -> void:
	visible = on
	for s in find_children("*", "CollisionShape2D", true, false):
		s.set_deferred("disabled", not on)
	# 顺带：隐藏的帧不该跑动画/逻辑
	process_mode = Node.PROCESS_MODE_INHERIT if on else Node.PROCESS_MODE_DISABLED
```

**实际做法**（`scripts/frame_data.gd`）：

```gdscript
const CHAR_RADIUS := 7.0

func is_free(at: Vector2) -> bool:
	var probe := Rect2(at.x - CHAR_RADIUS, at.y - CHAR_RADIUS,
		CHAR_RADIUS * 2.0, CHAR_RADIUS * 2.0)
	for r in solid_rects:
		if (r as Rect2).intersects(probe):
			return false
	return true
```

`timeline.gd:86` 推时间时直接用 `frames[target].is_free(char_pos)` 判定——
**目标帧根本没被实例化，也能做重叠检测。** 这是旧方案做不到的。

### 3.4 时间轴移动的碰撞判定

时间模式下角色位置不变，但每推进一步都要检查：

> **如果目标帧里，角色的碰撞盒和固体重叠 → 卡住，推不过去。**

**反馈不要「弹回去」**（那是惩罚），要「顶住了」：
- 轻微顿帧
- 屏幕轻微震动
- 低频闷响

**已实现**（`scripts/timeline.gd:78` `step_time()` + `main.gd:171` `_on_bump()`）：
判定失败发 `bump` 信号 → `world_view.kick_shake(2.0)` 震屏 2px + 玩家后仰 `bump_kick` + HUD 刻度红环闪一下。
**判定是纯数学，同一帧立即反馈**，不需要等物理帧。

> **注意这条会限制「楼层」玩法。** 现在的判定是「目标帧这个坐标有没有 solid」，
> 所以「在二楼推时间、回到只有一层的过去、人落到屋顶上」**不会发生**（会被顶住）。
> 要支持它得改成「查目标帧该坐标不高于当前高度的最高可站表面」——
> 方案、改动范围、工时都写在 `docs/house-spec.md` §8（用户 11/19 拍板降到 P3，不一定做）。

### 3.5 场景继承链（**已废弃，只留实测数据**）

> **⚠️ 这一节记录的方案没有采用。** 实际用的是 `frames.json` 纯数据。
> 留在这里只是因为这些是**真实测出来的数**，将来若帧数暴涨到几百帧可以回头参考。

用 Godot 的**继承场景**做帧，每帧只存相对上一帧的改动。

**30 层实测数据**（真的测了 30 层，不是估的）：

| 项 | 数据 |
|---|---|
| base 场景 | 2800 B |
| 每帧增量 | **约 225 B** |
| 30 帧总计 | 9563 B |
| 若全量复制 | 84000 B |
| **加载 30 帧** | **34.4 ms** |
| **实例化 30 帧** | **3.9 ms** |
| **刷完 30 帧 ×60 遍** | **2.66 ms**（1800 次切换） |

**性能完全不是问题。**

**但继承是纯累积的**：第 29 帧 = 前 29 帧所有差分的和。忘了恢复的永远回不来。
好消息是**可以覆盖**（实测 `visible` 能改回 true），但必须**显式写出来**。

### 3.6 继承结构建议：分叉，不要长链（**同样已废弃**）

> 实际实现里没有场景继承，五帧是同一个 JSON 里的五个数组元素。
> 下面的「分叉 vs 长链」取舍结论仍然成立，只是载体从场景变成了数据。

```
				base.tscn（所有元素、原始位置、默认状态）
			   ╱     │      │      │      ╲
			A1     A2     A3     A4     A5        ← 5 个锚点帧，各自继承 base
			│      │      │      │      │
		 t1_1   t2_1   t3_1   t4_1   (终点)
		 t1_2   t2_2   t2_2   ...
```

| | 长链 | 分叉（推荐） |
|---|---|---|
| 看某帧全貌 | 得加 20 个文件 | **一个文件，几行** |
| 某段出错 | 污染后面所有 | **只影响本段** |
| 过渡链长度 | 24 | **4~5** |

**过渡链超过 5 张玩家分辨不出来。**

**在数据方案里这条变成了**：每帧的 `shapes` 写全量（不写差分），
因为 JSON 里做差分要写合并逻辑，而全量写反而更省心——
五帧加起来才 170 行。**过渡帧将来也一样：每条都是独立的全量描述。**

### 4.2.1 跨帧流转：真本《水簿》与那个暗龛（`story.md` §5.6）

**这是本项目唯一一个「同一件东西在不同帧里位置不同、状态也不同」的线索**，也是最容易做错的一个。

| 帧 | 暗龛 | 真《水簿》在哪 |
|---|---|---|
| **A1 1926** | 磨坊是磨坊，**还没有暗龛** | 沈万山随身带着，天天记 |
| **A2 1951** | 账房新砌出暗龛，**里面空着** | 仍在沈万山身上（他这年停笔，但没放进龛里） |
| **A3 1976** | 同一个暗龛，沈德昌挖地基时**从里面挖出真本** | 从暗龛出土 |
| **A5 2026** | 磨坊早不存，超市门厅摆着上磨盘 | 真本早已不在现场 |

- **A2 的空龛是暗示，不是答案。** 它只让玩家知道「这地方放过东西」。
- **A3 那一刀**：沈德昌看到祖父的手记，才决定把知情人一起封进地基 —— **真相本身就是凶器**。
- **墙的做法**：全是砖墙、**不上油漆**。最外侧原墙 = 旧砖；A2 新砌的暗龛墙 = 新砖；那块能拿下露出暗龛的砖 = 第三档。色差只能是砖的新旧。
- **取消「施工信息」提示牌**（用户 11/19 拍板）：房型和墙色的大变化，玩家在时间轴来回切时自己看得出来，不需要牌子教。

**这条对数据格式的要求**：证物不能写全局的 `pos` / `texture`，必须挂在**每帧的 `states`** 下（格式见 `docs/house-spec.md` §4.6.4）。
落点：`mill_a1` 有账桌无暗龛 → `mill_a2` 有暗龛（空）+ 账桌 → `shen_a3` 挖出的暗龛在磨坊原址（那时已是粮站）。

三条检视文本（只写看到什么）：

- A2 · 挪动的那块砖：`东数第三块砖，灰缝是新的。按了一下，砖往里陷了半分。`
- A3 · 同一位置挖出的暗龛：`墙基里凿出一个方龛，油布包着一本线装账，边角都卷了。`
- A3 · 沈德昌的反应（只写后果）：`粮站地基那一段，停工了三天。`

### 4.3 写作纪律（违反就破坏设计）

1. **只写看到什么，不写意味着什么**
   - ✅「地上有一圈比周围颜色深的方形痕迹」
   - ❌「这里曾经有一座建筑」
2. **日记只记行为和数字，不记判断和动机**
   - ✅「放水三刻。未告陆家。」
   - ❌「我很内疚，但我不敢说」
3. **真相不能靠「又发现一份文件」**
   - 「真假两份记录」全片只用一次，其余必须是物理证据（补丁、排水管、界碑）
4. **人嘴只给方向，物证才给结论**
   - 旁听和对话**永远不进归档表**；玩家听完十个版本的闲话，仍然是零
5. **时间轴里没有声音**
   - 一晃几十年，旁边有人在说话也听不清——**所以那一段干脆不做**

**完整五条见 `story.md` 附三。**

### 5.1 分辨率

| 项 | 值 |
|---|---|

| 缩放 | fractional（1080p=1.5× / 1440p=2× / 4K=3×），`project.godot` `stretch/mode="canvas_items"` + `scale_mode=0` |
| 风格 | 像素风，俯视 3/4（星露谷式） |
| 光线方向 | **统一从左上来** |

**这个数一旦定了就不能改**，改了所有素材重画。（已定案 1280×720，见 `docs/DECIDE-stardew-visual.md` D7。）

### 5.2 图层拆法：省六倍工作量

**不要每帧都画完整画面。** 你的 25 帧 × 10 个元素 = 300 张图，画不完。

拆成三层：

| 层 | 是什么 | 数量 | 谁做 |
|---|---|---|---|
| **base** | 轮廓/结构（房子→废墟→空地） | ~30 | 美术 |
| **overlay** | 裂缝、杂草、焦痕、木板、碎石、脚手架 | ~14 | 美术 |
| **tint** | 年代调色板 | 0 张 | 程序 |

```
30 + 14 = 44 张图  →  撑起 25 帧
```

**从 300 降到 44，六倍。**

**overlay 是跨元素复用的**：一片杂草能盖在小路、农田、房子墙根上。
**base 是仓库，overlay 是 diff，tint 是分支颜色。**

### 5.3 过渡帧不用画

如果状态是**数据**（不是 25 个手摆的场景），两个状态之间插值就得到过渡帧：

- overlay 透明度 lerp（杂草慢慢长出来）
- tint lerp（暖黄 → 病绿 → 灰褐）
- **只有结构性变化需要手画关键帧**（房子塌了、路铺柏油）

**25~30 帧在这个架构下不是 30 张图，是 30 个数据点。**

## §6.5 Git：本地 init 与远程推送是两回事

**是的，`git init` 只是在本地建仓库。** 它不联网、不需要账号、不碰 GitHub。

```
git init      → 在本机创建一个 .git 文件夹（本地版本库，仅此而已）
git remote add → 告诉本地仓库"远程在哪"（仍然不联网）
git push      → 这才真正联网上传到 GitHub
```

**三步是分开的，顺序不能乱，也不需要一次做完。**

### 6.5.1 现在这一步：本地 init + 首次提交

**在项目根目录 `shift/` 执行**（PowerShell）：

```powershell
cd "D:\Desktop\VibeCoding\godot_project\github_game_off_shift\shift"

git init
git add -A
git commit -m "chore: 初始化项目，故事文档与转接文档"
```

**此时已经可以开始正常开发了。** 之后的提交：

```powershell
git add -A
git commit -m "feat: 时间轴切换"
```

### 6.5.2 明天做完草稿后：推到 GitHub

1. 在 GitHub 网页上 **New repository**，名字随意（比如 `shift`），
   **选 Public**（比赛硬性要求公开），**不要勾选** "Add a README" / ".gitignore"
   —— 因为本地已经有这些文件了，勾了会产生冲突。
2. 复制页面给的仓库地址，然后：

```powershell
git branch -M main                                  # 分支名统一成 main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

**`git remote` 和 `git push` 需要 GitHub 账号认证**（首次会弹浏览器登录，或要填 PAT）。

### 6.5.3 现有配置文件可直接用

## §9. 和 SHIFT 主题的关系

**写进 itch 页面的介绍里，这是评委第一个看的：**

> **时过境迁，沧海桑田，我仍在此处看云卷云舒。**

> *The world turns over. He stays where he is, watching the clouds pass.*

空间冻结、时间可动、位置不变——**这既是玩法，也是这个故事的主题。**

**另外一句**（讲「为什么时间轴里没有人」）：

> **想要人，时间就冻住；想让时间走，人就没。**
> **一个归档员查了一辈子，从来没有见过任何一个人发生变化。**

### 9.1 为什么村里有人（2026-11-19 修正）

**旧版这里写着「2026 年村里没人了，所以玩家只有物件」——这句话是错的，已删。**

A5 有超市、小学剪彩、玩具店租约，那不是一个空村。
**「没有 NPC」原本是排期决定，不是叙事必然，不该写成设定。**

现在的口径：

| | 时间轴 | 空间轴 |
|---|---|---|
| 人 | **不在**（看不见、听不见、不能对话） | **在**（听得见、能对话） |
| 时间 | **在流动** | **不动** |

> **你永远不能同时拥有「流动的时间」和「人」。**

主角在时间轴上一晃几十年，旁边就算有人在说话也听不清——**所以那一段干脆不做。**

**这条零成本：不做，它就是设定。**

NPC 的完整规则见 `docs/npc.md`。三条铁律：**他不能改变任何事 / 对方转身就忘 / 他永远不回答「你是谁」。**
